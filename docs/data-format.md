# Data Format

DPNet expects each task to live in a task directory under `database/`. The task
directory may be nested by category, such as `database/distribution/bbbp`.

## Task Directory

```text
database/<category>/<task>/
|-- raw/
|   `-- <task>.csv
|-- task_meta.json
|-- duplicates.csv
`-- processed/
    `-- <task>/
        |-- <task>.json
        |-- train.csv
        |-- valid.csv
        `-- test.csv
```

`duplicates.csv` and `processed/` are generated by preprocessing. A new task
only needs `raw/<task>.csv` and `task_meta.json`.

## Raw CSV

Raw CSV files must include a SMILES column and one or more label columns. The
actual column names are declared in `task_meta.json`.

Example:

```csv
smiles,label
CCO,0
CCN,1
```

## Task Metadata

`task_meta.json` describes how DPNet reads and exports the task.

```json
{
  "name": "bbbp",
  "seed": 42,
  "id_col": null,
  "smiles_col": "smiles",
  "labels": [
    {
      "id": "bbbp",
      "label_col": "label",
      "problem_type": "binary",
      "num_classes": 2
    }
  ],
  "strict_test": true,
  "split_method": "scaffold",
  "split_config": {
    "perimeter_max_samples": 10000
  },
  "processed_dir": "processed",
  "extra_cols": []
}
```

Important fields:

- `name`: task name used for output directory and metadata file names.
- `id_col`: optional sample identifier column. If missing or null, preprocessing
  generates `cid`.
- `smiles_col`: raw SMILES column to canonicalize and export as `smiles`.
- `labels`: one or more prediction targets. `problem_type` can be `binary`,
  `multiclass`, or `regression`.
- `strict_test`: controls the scaffold split behavior used by `dpnet process`.
- `split_method`: optional split method for `dpnet process`. Supported values
  are `scaffold`, `random`, and `perimeter`; missing values default to
  `scaffold`.
- `split_config`: optional split settings. `perimeter_max_samples` defaults to
  `10000`; when perimeter is requested above this limit, the CLI logs a warning
  and falls back to scaffold split.
- `processed_dir`: relative directory for processed split output.
- `extra_cols`: optional columns to keep in processed splits.

## Processed Splits

After `dpnet process <task>`, DPNet writes:

- `train.csv`
- `valid.csv`
- `test.csv`
- `<task>.json`

Processed split files use normalized column names:

- `cid` or the configured ID column.
- `smiles`.
- One column per label, named by each label `id`.
- Any configured `extra_cols`.

These processed split files are the expected input for `DPNet(...)` and
`dpnet run`.

## Loading Processed Data

Python API:

```python
from dpnet import DPNet

dpnet = DPNet("database/distribution/bbbp/processed/bbbp")
train_data = dpnet.datasets["train"]
sample = train_data[0]
```

CLI baseline:

```bash
dpnet run bbbp --task-dir database/distribution/bbbp/processed/bbbp
```
